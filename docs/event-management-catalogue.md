# EventManagement catalogue

This catalogue is the reviewable source for the required event inventory. Events are immutable facts and their dispatch is synchronous through Tempest; calling `event()` does not prove a surrounding database transaction committed, and dispatch after a commit can be lost if the process stops before dispatch. No middleware currently writes an event log, PREMIS record or client notification. Domain owners must dispatch only after their fact is established.

The installed Tempest 3 EventBus takes `string|object` events, wraps its resolved handlers in discovered middleware, and calls each middleware with the event and next callable. Middleware ordering comes from Tempest's middleware collection and `#[Priority]`; a thrown handler or middleware exception propagates and stops the remaining chain. The EventBus exposes no transaction commit hook or after-commit guarantee. These EventManagement middleware classes use the native interface but carry `#[SkipDiscovery]` until their external recorder or delivery adapter and its failure policy exist.

The API uses specific IDs and version references, not copies of mutable domain records. Where the future owner has not fixed a detailed contract, the current constructor carries only stable subject and operation identities; those fields are deliberate initial contracts, not a claim that the deferred subsystem exists. Arrays in constructors are lists of stable IDs or evidence references as named by the property.

Classification is explicit and conservative. `DurableHistory` marks candidates for operational recording, not existing durable storage. `PremisSignificant` marks a subset for a future archival recorder. No event is marked client-visible pending an approved public projection. `TransientObservation` identifies frequent checkpoints that should not be durable by default. Unmarked events remain unclassified pending department review.

Coverage stages are independent: **Defined** means the typed class exists; **Emitted** means production code dispatches it; **Verified** means tests verify correct emission and non-emission; **Consumed** means a production handler, projection or client feature uses it. All definitions below are currently defined only. The automated audit leaves Emitted, Verified and Consumed unverified: source text cannot establish these guarantees. It checks class definitions independently and does not fail merely because an event has no emitter.

Run `php tools/audit-event-catalogue.php` from Core to compare the documented inventory with the source tree and print the four coverage stages per event.
